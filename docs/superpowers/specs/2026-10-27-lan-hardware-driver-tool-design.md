# HwOps 硬件运维助手 — 设计文档

- 日期：2026-10-27
- 状态：待评审
- 工作名：HwOps（同事端「硬件助手」，运维端「运维台」）
- 目标平台：Windows 10 22H2 / Windows 11，x64

## 1. 背景与目标

硬件运维在帮同事装驱动时，经常缺少对方机器的准确信息（主板型号、BIOS 版本、问题设备、硬件 ID），线下跑一趟成本高。目标是做一个**内网可用的双端工具**：

1. 同事端双击即用，本地生成完整体检报告与驱动下载指引。
2. 运维端在同一内网主动拉取同事机器的硬件参数，匹配驱动下载页，并把链接直接在对方屏幕上打开。
3. 不架设中央服务器，不要求同事机器开放入站端口，不要求管理员权限。
4. 驱动只提供**官方下载页链接与建议顺序**，不做自动下载安装。

### 成功标准

- 同事粘贴协助码后，运维端 30 秒内看到完整报告。
- 硬件采集耗时 < 3 秒（常规办公机）。
- 同事端断网、运维端未运行时，本地报告功能完全可用。
- 常见 DIY 主板（华硕/微星/技嘉/华擎/七彩虹/铭瑄）与主流品牌机（联想/戴尔/惠普/华硕/华为/小米/机械革命）能命中官方支持页。
- 在装有 360 / 火绒的机器上不被拦截，或完成白名单报备后有明确操作指引。

## 2. 用户与场景

**主要用户**：硬件运维（本工具的操作者，具备局域网内运维职责）。

**次要用户**：被协助的同事（非技术用户，愿意运行一个绿色 exe，不接受复杂配置）。

**核心场景**

1. 同事说「电脑缺驱动/设备有感叹号」。
2. 运维通过聊天发送「硬件助手.exe」和一个协助码（`192.168.1.20:47821#482913`）。
3. 同事双击运行，粘贴协助码，点「允许」。
4. 运维端出现该机器，点击采集，看到主板/BIOS/问题设备/驱动建议。
5. 运维点击「在对方电脑打开」，同事屏幕上直接打开官方驱动页；或复制链接发聊天。
6. 若同事端未运行或网络不通，运维让同事自行双击查看本地报告，把报告或截图发回。

**明确不是本工具的场景**：远程控制桌面、传文件、监控员工、批量静默部署、自动安装驱动。

## 3. 约束与前提

| 约束 | 内容 |
|---|---|
| 网络 | 同一内网、TCP 可达；两边均可访问外网；可能存在 VLAN 隔离与 WiFi 客户端隔离 |
| 系统 | Windows 10 22H2 / Windows 11 x64 为主 |
| 权限 | 同事端以标准用户运行；不要求 UAC 提权；主流程不要求开放入站防火墙（自动发现开启时除外） |
| 安全软件 | 同事机器普遍安装 360 / 火绒等国产杀软 |
| 基础设施 | 不架设常驻服务器、不安装 Windows 服务、不开机自启（可选开关，默认关） |
| 分发 | 绿色单文件夹（exe + 规则文件），共享盘或聊天分发 |

## 4. 方案选型

### 4.1 连接方向：反向连接（已选定）

| 方案 | 结论 |
|---|---|
| A. 反向连接：运维端监听，同事端出站连接 | **采用**。同事端零防火墙配置、零提权 |
| B. 正向监听：同事端监听，运维端扫描 | 放弃。标准用户无法放行入站，跨网段易失败 |
| C. 仅本地报告 | 作为降级模式内置在同事端中 |

辅助机制：UDP 广播信标（默认关闭）。开启后同事端可在防火墙允许的情况下免粘贴自动发现运维端；不作为主流程依赖。

### 4.2 技术栈：C# / .NET 10 WinForms 自包含单文件（已选定）

| 候选 | 取舍 |
|---|---|
| C# .NET WinForms | **采用**。WMI 原生（System.Management）、托盘与表格原生、Kestrel 内嵌、两端共享核心库 |
| Go + 浏览器 UI | 放弃。WMI 依赖 PowerShell 子进程，常驻托盘体验弱，单文件 exe 杀软误报率偏高 |
| Python + PyInstaller | 放弃。体积大、启动慢、误报率高 |

目标框架 `net10.0-windows`（LTS），`win-x64`，`PublishSingleFile` + `SelfContained`。开发机已具备 .NET 10 SDK 与 Desktop Runtime；发布的单文件自包含 exe 在目标机免装运行时。单文件体积实测约 50 MB（51,677,205 字节）。若体积成为阻碍，可另出一个依赖 Desktop Runtime 的精简构建。

### 4.3 驱动能力边界（已选定）

- 只给**官方下载页链接 + 建议顺序**，可在同事屏幕上代开链接。
- 不做自动下载、签名校验、静默安装（等同于重做驱动精灵，风险与工程量不可控）。
- 精确直链无公开全量 API，准确率依赖规则库覆盖度；工具提供「从设备一键新增规则」的积累机制。

### 组件划分

| 组件 | 职责 | 依赖 |
|---|---|---|
| `HwOps.Core` | 数据模型、WMI 采集器、硬件 ID 解析、规则匹配、协议 DTO、签名工具 | .NET 10 |

## 6. 连接与配对流程

### 6.1 首次配对

1. 运维端打开「接收模式」，Kestrel 监听 `0.0.0.0:47821`，生成协助码 `<运维端IP>:47821#<6位PIN>`。PIN 有效期 10 分钟，可手动刷新；有效期内可供多台机器配对，刷新后旧 PIN 立即失效。运维端同时显示本机所有 IPv4 地址供跨网段选择。
2. 运维把协助码发聊天。同事双击运行同事端，点「连接运维台」，粘贴协助码。
3. 同事端解析出运维端地址，弹出确认框：

   ```
   运维台 OPS-PC (192.168.1.20) 请求查看本机硬件信息
   采集内容：系统、主板、BIOS、CPU、内存、显卡、存储、网络、外设与驱动状态
   不涉及：文件、屏幕、账号、已安装软件
   [允许并记住]  [仅本次]  [拒绝]
   ```

4. 允许后，同事端生成 128 位随机令牌，携带 PIN 调用 `POST /v1/session`；运维端校验 PIN 与有效期，保存机器信息与令牌，返回成功。
5. 同事端将令牌用 DPAPI 加密保存到 `%LOCALAPPDATA%\HwOps\agent\state.json`；运维端同样保存到 `%LOCALAPPDATA%\HwOps\console\state.json`。
6. 同事端进入长轮询；运维端列表中出现在线机器。

### 6.2 后续连接（自动）

- 同事端每次启动且「允许内网协助」开启时，若已配对过运维端，自动出站重连，指数退避：5s → 15s → 30s → 60s（上限）。
- 运维端 IP 变化时自动重连失败，提示同事重新粘贴协助码；旧配对保留，可手动清除。
- 运维端关闭后，同事端保持本地功能，连接状态显示「等待运维台」。

### 6.3 令牌与签名

- 令牌：32 字节随机数，Base64 编码，DPAPI 加密存储。
- 配对完成后的每个请求携带：`X-HwOps-Machine`、`X-HwOps-Timestamp`、`X-HwOps-Nonce`、`X-HwOps-Signature`。
- 签名：`Base64(HMAC-SHA256(token, method + "\n" + path + "\n" + timestamp + "\n" + nonce + "\n" + SHA256(body)))`。
- 服务端校验时间窗 ±120 秒、Nonce 5 分钟内不重复；响应同样签名，双向校验。
- MVP 不启用 TLS；威胁模型为受信内网，传输内容为硬件参数。后续可加自签名 TLS 与证书指纹固定。

### 6.4 UDP 信标（可选，默认关闭）

- 运维端接收模式开启时每 3 秒广播 `{"magic":"HWOPS1","name":"OPS-PC","port":47821,"proto":1}` 到 `255.255.255.255:47820` 与各网卡子网广播地址。
- 同事端开启「自动发现」后监听 UDP 47820，收到后在界面显示「发现运维台 OPS-PC [连接]」，仍需本地授权弹窗。
- 该功能需要同事端接收 UDP 入站，可能触发防火墙提示或失效；不开启不影响主流程。

## 7. 通信协议

运维端监听端口默认 TCP 47821，可在设置中修改（47821–47899）。所有请求/响应为 JSON（UTF-8）。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/v1/health` | 无需鉴权；返回运维端名称、协议版本，用于协助码连通性测试 |
| POST | `/v1/session` | 建链。PIN 模式：首次配对；Token 模式：HMAC 签名 |
| POST | `/v1/commands/poll` | 长轮询取指令，最多挂起 25 秒；无指令返回 204 |
| POST | `/v1/report` | 上报硬件快照 |
| POST | `/v1/command-result` | 上报指令执行结果 |

### 请求示例

```json
POST /v1/session
{
  "protocolVersion": 1,
  "agentVersion": "0.1.0",
  "rulesVersion": "2026.10.1",
  "machine": { "id": "9f2c...", "hostname": "PC-01", "os": "Windows 11 23H2" },
  "auth": { "mode": "pin", "pin": "482913", "token": "<base64>" }
}
```

```json
POST /v1/commands/poll
{ "sessionId": "s-01" }
```

### 指令类型

```json
{ "commandId": "c-18", "type": "collect", "payload": {} }
{ "commandId": "c-19", "type": "open-url", "payload": { "url": "https://..." } }
{ "commandId": "c-20", "type": "sync-rules", "payload": { "rulesVersion": "2026.10.1", "rules": [] } }
{ "commandId": "c-21", "type": "ping", "payload": {} }
```

- `collect`：同事端立即采集并调用 `/v1/report`。采集期间运维端显示「采集中」。
- `open-url`：仅允许 `http/https`，同事端用默认浏览器打开，并在连接日志记录完整 URL。
- `sync-rules`：覆盖同事端本地规则缓存，用于本地报告使用最新规则。
- `ping`：保活与延迟测量。

### 会话状态

- 同一机器允许一个活动会话；新会话建立时旧会话标记失效。
- 运维端重启后会话失效，同事端自动重连重建。
- 双方 `protocolVersion` 不一致时，`/v1/session` 返回明确错误码与提示，不降级运行。
- 指令由运维端排队；同事端按 `commandId` 去重后执行，避免重试导致重复打开链接。

### 8.1 机器指纹

## 9. 硬件采集

使用 `System.Management`（WMI/CIM），每类查询独立 try/catch，单查询超时 5 秒，整体目标 < 3 秒。

| 数据 | 来源 |
|---|---|
| 系统/型号/序列号 | `Win32_ComputerSystem`、`Win32_ComputerSystemProduct`、`Win32_OperatingSystem` |
| 主板 | `Win32_BaseBoard` |
| BIOS | `Win32_BIOS` |
| CPU | `Win32_Processor` |
| 内存 | `Win32_PhysicalMemory` |
| 显卡 | `Win32_VideoController` |
| 驱动信息 | `Win32_PnPSignedDriver`（按 DeviceID 与 PnP 设备关联） |
| 全部设备与问题代码 | `Win32_PnPEntity`（`ConfigManagerErrorCode`） |
| 存储 | `Win32_DiskDrive`、`MSFT_PhysicalDisk`（备用） |
| 网络 | `Win32_NetworkAdapter` |
| 声音 | `Win32_SoundDevice` |
| 电池 | `Win32_Battery`（笔记本） |

约束：

- 只读查询，不修改系统状态。
- 不采集用户名、已安装软件、浏览记录、文件。
- 硬盘序列号等敏感字段可能需管理员；取不到的字段显示「—」，查询失败原因记入「采集告警」。
- 采集为 11 个任务并行（drivers→devices 同任务串行），新进程实测约 2 秒；设 10 秒整体预算，超时类别记「超过采集时间预算，已跳过」并继续返回快照。
- 显卡与网卡视图排除 `ROOT\`/`BTH\`/`USBSTOR\` 虚拟适配器，避免给向日葵/UU 虚拟显示器生成驱动建议；`devices` 保留设备管理器式的全量视图。
- 序列号占位值（如 "System Serial Number"、"To be filled by O.E.M."）归一为 null。
- 采集器实现 `IHardwareCollector` 接口，UI 与测试可注入假数据。

## 10. 驱动匹配

### 10.1 五层规则（优先级从高到低）

| 层 | 匹配依据 | 典型用途 |
|---|---|---|
| 1. 设备级 | 硬件 ID（PCI VEN/DEV/SUBSYS、USB VID/PID） | 显卡、常见无线网卡/蓝牙 |
| 2. 整机 OEM | `Win32_ComputerSystem` 厂商 + 型号/序列号 | 品牌机/笔记本，一页覆盖全部驱动 |
| 3. 主板厂商 | `Win32_BaseBoard` 厂商 + 型号 | DIY 台式机，一页覆盖芯片组/网卡/声卡/蓝牙 |
| 4. 设备厂商 | 由 VEN/VID 映射厂商下载中心 | 设备级规则缺失时的厂商搜索页 |
| 5. 通用兜底 | Microsoft Update Catalog 按硬件 ID 搜索 | 未知设备、白牌设备 |

规则层号只用于选出每类设备的最佳链接；界面呈现顺序按 10.4 的「建议动线」，不按规则层号排序。

```json
}
```

- 占位符：`{hardwareId}`、`{boardProduct}`、`{oemModel}`、`{serial}`、`{vendorId}`、`{deviceId}`、`{className}`。
- 规则按层与具体度排序；同级内「精确 ID > 前缀 > 正则」。
- 具体 URL 路径在实现时逐条核验；厂商改版时只改规则文件，不改代码。
- 外部 `rules.json` 覆盖内置规则（按 `id` 合并）；非法 JSON 时回退内置规则并告警。运维端规则存于 `%LOCALAPPDATA%\HwOps\console\rules.json`，同事端缓存于 `%LOCALAPPDATA%\HwOps\agent\rules.json`。
- 建链时同事端上报本地 `rulesVersion`；运维端发现不一致即下发 `sync-rules`，同事端覆盖缓存并重新渲染本地报告。
- 运维端提供「从选中设备新增规则」，写入外部规则文件；可导入/导出规则包。

### 10.3 种子规则范围

- 主板：华硕、微星、技嘉、华擎、七彩虹、铭瑄、昂达、映泰。
- 整机：联想/ThinkPad、戴尔、惠普、华硕、宏碁、华为、小米/Redmi、荣耀、机械革命。
- 设备：NVIDIA、AMD、Intel（显卡/无线/蓝牙）、Realtek、联发科、高通、博通；Synaptics/ELAN 触控板、Goodix 指纹等笔记本外设。
- 首批 40–60 条，全部附「备注」说明在页面内如何定位对应驱动。
- 通用兜底规则始终存在，未命中不会出现空结果。

### 10.4 输出形态

每台机器给出「建议动线」：

1. 品牌机先开 OEM 支持页；DIY 机先开主板支持页。
2. 再处理独立显卡。
3. 最后按 `problemDevices` 逐项给出链接。
4. 仍无法定位时，用硬件 ID 搜 Microsoft Update Catalog。

## 11. 界面设计

### 11.1 同事端（HwOps.Agent.exe）

主窗口 960×700（最小 800×580）：

- 顶部概况：主机名、Windows 版本、主板、BIOS、采集时间。
- 标签页：概况 / 设备列表 / 问题设备 / 驱动建议。
- 底部状态栏（M1 实际内容）：采集时间、设备数、问题数；协助与连接状态属 M2。
- 按钮：重新采集、连接运维台、导出报告（HTML/JSON）、设置。
- 设置：允许内网协助、开机自启（HKCU Run，默认关）、自动发现（默认关）、清除信任、打开日志目录。
- 授权弹窗：显示运维端名称/IP、采集范围、允许/拒绝；选择「仅本次」不保存令牌。
- 连接日志：时间、事件（配对、采集、代开链接、断开、重连）、对方标识；同时写入 `%LOCALAPPDATA%\HwOps\agent\agent.log`（滚动，上限 5 MB）。
- 关闭窗口最小化到托盘；托盘菜单含「打开面板」「暂停协助」「退出」。

### 11.2 运维端（HwOps.Console.exe）

主窗口 1200×800：

- 工具栏：接收模式开关、生成协助码（显示 IP、端口、PIN、复制按钮）、规则库、设置。
- 左侧机器列表：主机名、IP、主板、系统、状态（在线/等待）、最后上线时间。
- 右侧详情：概况 / 设备 / 问题设备 / 驱动建议；每台机器一个「采集」按钮。
- 驱动建议页：每条含标题、匹配依据、链接、「复制链接」「在对方电脑打开」「浏览器打开」。
- 导出：单文件 HTML（内联样式，含全部链接）与 JSON 快照。
- 规则库：列表、搜索、编辑、从设备新增、导入/导出、版本号显示。
- 设置：监听端口、信标开关、日志目录（默认 `%LOCALAPPDATA%\HwOps\console\console.log`）、清除配对。
- 关闭窗口退出监听，不驻留后台。

### 11.3 报告导出

- HTML：单文件，包含系统概况、设备表、问题设备高亮、驱动建议（可点击）、采集时间与工具版本。
- JSON：原始快照，便于归档或后续工具消费。

## 12. 安全与隐私

- 同事端只出站，不监听 TCP；UDP 自动发现默认关闭。
- 首次配对必须由同事在本地弹窗授权；令牌可随时清除。
- 除 `/v1/health` 与首次 PIN 配对请求外，所有请求均 HMAC 签名，时间窗 + Nonce 防重放；令牌 DPAPI 加密存储。
- 采集范围固定为硬件与驱动信息，不含文件、屏幕、账号、软件清单。
- 对同事机器的唯一主动操作是「打开链接」，URL 限制 http/https，同事端日志可见。
- 无隐蔽行为：托盘常驻可见、连接日志可查、无内核驱动、无计划任务、默认不写自启项。
- 使用前提：仅限公司内网、经授权的运维场景；工具界面与文档中明确用途。
- 残余风险：MVP 不加密传输；同网段嗅探者可看到硬件参数，并可能在首次配对时截获令牌（后续请求只含签名，不含令牌）。硬件数据敏感度低，且首次配对需运维端 PIN。若后续合规要求提高，启用 TLS + 证书固定。

## 13. 异常处理

| 场景 | 行为 |
|---|---|
| 某类 WMI 查询失败/超时 | 该项标记「未采集到」，其余正常；写入 warnings |
| 无管理员权限 | 字段显示「—」，失败原因进采集告警 |
| 运维端未运行 | 同事端退避重连；本地报告与导出照常可用 |
| 网络中断 | 会话失效，自动重建；采集中断则本次采集失败并提示重试 |
| 协助码错误/过期 | 明确提示「协助码无效或已过期，请运维端重新生成」 |
| PIN 错误 | 拒绝建链，记录日志，不泄露运维端信息 |
| 令牌失效/被清除 | 返回 401，同事端提示重新配对，不静默重试 |
| 端口被占用 | 运维端启动失败并提示更换端口（设置面板） |
| 跨 VLAN / AP 隔离 | 提示确认网络可达；AP 隔离无法解决，建议有线或同交换机 |
| 规则未命中 | 落到通用兜底链接（M3 提供新增规则入口） |
| 规则文件损坏 | 回退内置规则并告警 |
| 协议版本不一致 | 建链拒绝并提示升级对应端 |
| 导出目录不可写 | 提示另存为其他路径 |

## 14. 测试策略

### 14.1 自动化

- 单元测试：硬件 ID 解析（PCI/USB）、规则匹配优先级、URL 模板渲染、快照序列化/反序列化、HMAC 签名与校验。
- 集成测试：本机双进程通过 `127.0.0.1` 走完整流程（协助码 → 配对 → 采集 → 上报 → 打开链接 → 断线重连）。
- 采集器假数据：注入固定快照测试 UI 与规则引擎。

### 14.2 真机矩阵

- 系统：Windows 10 22H2、Windows 11（23H2/24H2）。
- 权限：管理员 / 标准用户。
- 安全软件：360、火绒、仅 Defender。
- 网络：同网段、跨网段、WiFi（含 AP 隔离场景）。
- 硬件：至少一台 DIY 台式机、一台品牌笔记本、一台老机器（2015 年前后）。

### 14.3 验收标准

- 首连 30 秒内看到报告；采集 < 3 秒；连续采集 10 次无内存增长异常。
- 断网时本地报告可用；重连后自动恢复。
- 360/火绒最新病毒库下无拦截，或已完成加白流程并记录操作步骤。
- 规则命中率：种子覆盖品牌的机器，问题设备链接命中率 ≥ 90%（以人工核对为准）。

## 15. 里程碑

### M1：采集与本地报告

- 解决方案骨架（Core / Agent）、WMI 采集器、规则引擎、种子规则、同事端 UI、HTML/JSON 导出、单元测试。
- 验收：Win10/11 上双击可用；断网可用；采集 < 3 秒。

### M2：内网拉取

- 运维端 Kestrel、协助码与配对、令牌/HMAC、长轮询、采集与代开链接、自动重连、多机列表、集成测试。
- 验收：两台真机完成首次配对与后续自动连接，30 秒内出报告。

### M3：打磨与分发

- 规则编辑器与规则同步、设置与开机自启、日志、UDP 信标（默认关）、报告导出完善、杀软真机测试与白名单材料、分发打包、一页式使用说明（协助码怎么发、同事怎么点、杀软提示怎么处理）。
- 验收：360/火绒通过；种子规则覆盖品牌验证；最终 exe 可在干净 Win10/11 上直接运行。

## 17. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 360/火绒误报（最高风险） | 同事端被拦截，方案不可用 | 不混淆不加壳；行为透明；默认不写自启；尽早真机测试；准备用途说明与哈希值；走公司白名单流程；必要时申请代码签名证书 |
| 运维端防火墙入站提示 | 首次监听被拦 | 运维本机点允许（专用网络）；文档给出操作步骤；端口可配置 |
| 厂商页面链接失效 | 驱动建议失效 | 规则与代码分离；规则带版本号；工具内可编辑；定期人工校验种子规则 |
| 跨 VLAN / AP 隔离 | 无法连接 | 主流程基于出站连接，通常可通；AP 隔离场景建议有线或同交换机；协助码支持跨网段 |
| 标准用户 WMI 字段受限 | 信息不完整 | 字段级降级显示；文档说明哪些字段需管理员 |
| .NET 自包含体积（实测约 50 MB） | 分发不便 | 共享盘分发；可另出依赖运行时的小体积构建 |
| Win10 已停止支持 | 安全与兼容退化 | 优先覆盖 Win11；Win10 22H2 兜底 |
| 规则维护成本 | 长期准确率下降 | 「从设备新增规则」降低录入成本；规则可导入导出共享 |

## 18. 决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 连接方向 | 反向连接（A） | 同事端零入站、零提权，标准用户可用 |
| 降级模式 | 内置本地报告 | 网络不可用时工具仍有价值 |
| 技术栈 | C# .NET 10 WinForms 自包含 | WMI/托盘/表格原生，双端共享核心；开发机已具备 .NET 10 运行时，目标机免装 |
| 驱动能力 | 链接 + 建议，不自动安装 | 自动安装工程与风险不可控 |
| 传输安全 | HTTP + HMAC 签名，暂不 TLS | 内网硬件数据，先解决可用性；TLS 预留 |
| 端口 | TCP 47821（可改），UDP 47820（信标，默认关） | 高位端口，冲突少 |
| 状态存储 | `%LOCALAPPDATA%\HwOps\{agent,console}` | 免管理员写入，DPAPI 加密令牌 |
| 自动启动 | 默认关，可选 HKCU Run | 降低杀软敏感度，尊重同事 |
| 产品命名 | HwOps / 硬件助手 / 运维台 | 便于沟通与分发 |
